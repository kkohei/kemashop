# フェーズ0 事前確認手順書 — Bカート仕様の確定

作成日: 2026-06-25
目的: 中継サーバー(`bcart-relay-server`)を実データ仕様に確定するため、Bカート側の不明点を実機確認で潰す。

---

## このフェーズで確定したいこと(残課題)

| # | 確認項目 | なぜ必要か | 確認方法 |
|---|----------|-----------|----------|
| A | プランでAPI / Webhookが使えるか | 使えないと前提が崩れる | 管理画面 / 営業に確認 |
| B | **Webhookの実ペイロード**(`event_type`の値・`data.object`の中身) | 通知の振り分けと会員ID取得の起点 | テスト送信をキャプチャ |
| C | **Bcart-Signature の署名仕様**(署名対象文字列) | 署名検証を正しく実装するため | ドキュメント / サポート |
| D | **受注APIのレスポンス項目**(会員ID・`logistic.status`の値) | 「誰に」「出荷通知を出すか」の判定 | API実行 or ドキュメント |
| E | ログイン方式(セッション/トークン・CAPTCHA・2要素の有無) | 生体認証ログインの実装可否 | ログイン画面を実機で確認 |

## 手順1: API / Webhook の利用可否(項目A)

1. Bカート管理画面にログイン
2. 「設定」→「外部連携」内に **「API」「Webhook」** の項目があるか確認
   - 項目が無い / グレーアウトしている場合 → プランのオプション。Bカート営業窓口に「APIとWebhookを使いたい」と問い合わせ
3. APIが使える場合、**パーソナルアクセストークン**を発行(スコープは受注・商品・在庫・会員の「参照」を中心に)
   - ⚠️ トークンは発行時の1回だけ表示。すぐ控える

---

## 手順2: Webhookの実ペイロードをキャプチャ(項目B・C)

中継サーバーには **キャプチャ機能**を入れてあります。これで実物のJSONを取得します。

### 2-1. 受け口を用意(どちらか)
- **本番VPSが既にあるなら**: `relay.example.com/webhook/bcart` をそのまま使う
- **まだVPSが無いなら**: 手元PCでサーバーを起動し、`ngrok` 等で一時的に公開
  ```bash
  cd bcart-relay-server
  npm install
  cp .env.example .env     # WEBHOOK_CAPTURE=true / WEBHOOK_VERIFY_STRICT=false のまま
  npm start
  # 別ターミナルで: ngrok http 8080  → 表示された https URL を使う
  ```

### 2-2. Bカートに登録
管理画面の Webhook 設定で、エンドポイントに以下を登録:
```
https://<あなたのURL>/webhook/bcart
```
- 署名シークレットを設定する欄があれば、任意の長い文字列を設定 →（後で `.env` の `BCART_WEBHOOK_SIGNING_SECRET` に同じ値を入れる）
- 通知イベントは「受注の新規・更新」を有効化

### 2-3. テスト発火
- 管理画面に「テスト送信」ボタンがあれば実行
- 無ければ、テスト用に1件 受注を作成 or 既存受注のステータスを更新

### 2-4. 結果を確認
`bcart-relay-server/data/webhook-capture.log` に1行ずつJSONが記録されます。
```bash
cat data/webhook-capture.log
```
**この中身(signatureヘッダーと body)をそのまま共有してください。** これを見て以下を確定します:
- `event_type` の実値(受注新規 / 受注更新を表す文字列)
- `data.object` に会員IDが含まれるか(無ければ受注APIで取得する設計のまま)
- 署名の形式

> 機密が含まれる場合は、会社名・氏名・住所などの値はマスクしてOKです(キー名と構造が分かれば十分)。

## 手順3: 受注APIのレスポンス確認(項目D)

トークンが発行できたら、テスト受注のIDで受注取得を試します(Bカート公式の Postman でも可)。
```bash
curl -H "Authorization: Bearer <APIトークン>" \
  "https://api.bcart.jp/orders/<受注ID>?complete=1"
```
確認したいフィールド:
- 会員IDの項目名(`member_id` / `customer_id` / `member.id` のどれか)
- `logistic.status` に入る値(未発送 / 発送済 などの正確な文言)
- 出荷判定に使える項目(送り状番号の有無など)

→ このレスポンス(マスク可)も共有いただければ、`src/bcart.js` の項目名と出荷判定を確定します。

---

## 手順4: ログイン方式の確認(項目E)

iPhoneの実機 or スマホブラウザで、Bカートの買い手向けログイン画面を開いて確認:
- [ ] ID/パスワードのフォームログインか(= 生体認証で自動入力しやすい)
- [ ] **CAPTCHA(画像認証)** が出るか(出ると自動ログインが困難)
- [ ] **2要素認証(SMS/メールコード)** があるか
- [ ] ログイン状態はどれくらい保持されるか(すぐ切れるか)

→ 結果を教えてください。CAPTCHA/2要素がある場合は、生体認証ログインの方式を調整します。

## あなたにお願いしたいこと(まとめ)

1. **手順1**: API/Webhookが使えるか(プラン確認)
2. **手順2**: Webhookテストを1回発火し、`data/webhook-capture.log` の中身を共有
3. **手順3**: 受注APIのレスポンス例を共有(トークンが出せたら)
4. **手順4**: ログイン画面のCAPTCHA/2要素の有無を共有

この4つが揃えば、中継サーバーのTODO(`event_type`判定・会員ID取得・署名検証・出荷判定)をすべて実値に確定できます。
まずは **手順1と手順4(管理画面を見るだけ)** から始めるのが手軽です。
